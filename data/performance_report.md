trade history. GBPUSD/XAUUSD/USDJPY data: Yahoo Finance daily candles,
2018-01-01 -> present. XAUUSD_DERIV: Deriv's public WebSocket API

## Data Integrity Note (read this first)

This revision fixes a real bug: `data/ledger.csv` had accumulated
duplicate rows for XAUUSD (91 duplicate raw rows, 65 duplicate memory
rows) and XAUUSD_DERIV, apparently from repeated backtest reruns without
a reset in between. This inflated the previously-reported XAUUSD numbers
(a prior version of this report showed 201 raw / 136 memory trades and a
463% memory PnL -- both wrong). The ledger and `data/learnings.md` have
been fully deduplicated and every backtest below was rerun from a clean
reset to produce verified numbers. **XAUUSD's true, correct figures are
110 raw / 19 memory trades** -- matching the very first report generated
for this pair.

**Read the raw-mode 95% CI carefully**: it spans from a 13.65% loss to an
81.21% gain. That's not a precise estimate -- it's what 6 real trades

tighter only because it's built from 2 trades; it is not evidence memory
mode is safer on Deriv, just that there isn't enough data yet to know.

### Why this dataset is thin, and what it means

Deriv only serves ~1 year of frxXAUUSD daily history via the public API,
producing 6 closed raw trades and 2 closed memory trades total. That is
not enough for statistically reliable Sharpe, Profit Factor, or Monte
Carlo estimates -- every number in this section should be read as "what
happened in the sample available," not "the expected performance of this
strategy on Deriv." The 8-year Yahoo-based XAUUSD backtest above remains
the more statistically grounded reference for gold; treat the Deriv run
as a data-source sanity check (does the strategy behave sensibly against
Deriv's actual quotes/spread) rather than a standalone validation.

## Live Forward-Testing (`--paper`)

`python -m src.replay --paper --symbol XAUUSD_DERIV` connects to Deriv's
live WebSocket tick feed, aggregates ticks into daily candles, and runs
the same crossover + memory decision logic used in backtesting --
logging what it would do to `data/paper_trades.csv`. **It does not place
real orders**; there is no broker authentication or order-execution code
in this project. Verified working end-to-end against Deriv's live feed
(received real ticks with live bid/ask, e.g. bid 4056.31 / ask 4057.04).
When a real bid/ask is available from the live tick (unlike historical
candles, which only carry a single quote), paper mode fills at the real
ask (buys) / real bid (sells) instead of the backtest's approximated
spread.
